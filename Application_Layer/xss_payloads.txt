1. REFLECTED XSS
* Payload Used: <script>alert('Reflected XSS Success')</script>
* Concept: Why does this attack disappear when you refresh the page?
Answer: It disappears on refresh because it is not saved on the server's database. The payload is "reflected" off the web server in a single response. For the attack to work again, the victim would have to click a specifically crafted link containing that payload.

2. STORED XSS (Cookie Theft)
* Cookie Value Stolen: session_id=admin_secret_99812_do_not_share
* Payload Used: <script>alert(document.cookie)</script>

3. CROSS-SITE REQUEST FORGERY (CSRF)
* Malicious URL Crafted: http://localhost:8081/transfer?to=Alice&amount=10
* Concept: What is the primary defense against CSRF?
Answer: The primary defense against CSRF is an Anti-CSRF Token (also called a Synchronizer Token). This is a unique, secret, and unpredictable value generated by the server for the user's session. The server checks for this token before processing any sensitive action (like a money transfer) to ensure the request actually came from the user and not a hidden link on another site.
