## 🛠️ Technical Framework Mapping (CIA & AAA)

This repository serves as a live lab environment governed by the following engineering frameworks to ensure a defensible security posture:

### Principle Implementation in this Portfolio

- **Confidentiality:** Application of strict file permissions, least-privilege administrative boundaries, and credential hygiene.
- **Integrity:** Git Version Control provides a **cryptographic audit trail** ensuring an immutable history for all configurations and source code.
- **Availability:** Cloud-synced repositories and decoupled architectural backups ensure service continuity after catastrophic local hardware failures.
- **Authentication:** Enforcement of secure access controls, hardware key binding, and **MFA** across developer profiles.
- **Authorization:** Granular control over the Linux security architecture, minimizing `sudo` exploit vectors through strict group mapping.
- **Accounting:** System monitoring logs, SIEM data streams, and Git Commit history act as the primary auditable record of work performed.

## ⚖️ Governance & Reflection

Governance provides the critical rules of engagement for technical tools. While an engineer can configure a firewall or deploy an IDS sensor, governance determines *which* traffic must be mitigated based on systematic **risk assessments**. This portfolio traces my evolution from local host-hardening up to advanced enterprise defense, demonstrating how business governance requirements translate directly into active, multi-layered defensive engineering controls.
